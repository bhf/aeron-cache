1. Open Grafana:
{{- if contains "LoadBalancer" .Values.grafana.service.type }}
   minikube service -n {{ .Release.Namespace }} {{ include "aeroncache-observability.grafana.fullname" . }}
   (or: make -C k8s/helm/aeroncache-observability port-forward-grafana  ->  http://localhost:{{ .Values.grafana.service.port }})
{{- else }}
   make -C k8s/helm/aeroncache-observability port-forward-grafana  ->  http://localhost:{{ .Values.grafana.service.port }}
{{- end }}
   These dashboards are pre-provisioned (folder: Aeron Cache):
     - Aeron Cache - Interface Apps            (HTTP/WS/SSE apps, OTel javaagent metrics)
     - Aeron Cache - Transport Gateway         (gateway sessions / requests / stream updates)
     - Aeron Cache - Cache Service             (cache request counters, clustered or ephemeral)
     - Aeron Cache - Transport / Media Driver  (raw Aeron media driver counters)

2a. The gateway / cache / media-driver dashboards are fed by the clustertools sidecar, which exports
    the shared Aeron media driver counters on /prometheus. The aeroncache-cluster, -ephemeral and
    -gateway charts carry the prometheus.io/scrape annotations by default, so just deploy whichever
    cache flavour you want and the panels populate automatically (no extra flag needed):

     make -C k8s/helm install-cluster       # clustered cache
     make -C k8s/helm install-ephemeral     # ephemeral cache
     make -C k8s/helm install-gateway       # transport gateway

2b. The "Interface Apps" panels stay empty until an interface app is scraped. Deploy the apps WITH
    the agent:

     make -C k8s/helm install-backend JAVAAGENT=true
     # or a single app, e.g.:  make -C k8s/helm install-http JAVAAGENT=true

   Without JAVAAGENT=true the apps run uninstrumented and expose no metrics (nothing to scrape).

3. Verify discovery in Prometheus:
     make -C k8s/helm/aeroncache-observability port-forward-prometheus  ->  http://localhost:{{ .Values.prometheus.service.port }}/targets
